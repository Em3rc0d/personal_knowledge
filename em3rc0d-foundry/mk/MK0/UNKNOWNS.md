# EM3RC0D Foundry — MK0 Unknowns

UNKNOWN is a valid state.

## U1 — First dogfood product

Which existing EM3RC0D project gives the best test of:

- re-entry;
- product contract;
- design/architecture;
- staged proof;
- reusable capital extraction?

Do not choose for convenience alone.

## U2 — Runtime home

Should the executable Foundry eventually live:

- inside personal_knowledge;
- in a separate em3rc0d-foundry repository;
- split into knowledge source + runtime package?

MK0 keeps knowledge here and defers runtime topology.

## U3 — Work taxonomy

The candidate source/intent classes need normalization against real work.

## U4 — Profiles and budgets

Which profiles exist, and should they have time/token/cost budgets?

Do not copy Railly’s exact minute values without evidence.

## U5 — Reusable asset maturity

A procedure, code primitive, UI component and design rule may need different maturity/eval requirements.

One universal ladder may be too coarse.

## U6 — Dependency cone representation

Path intersection works for code receipts, but product/design artifacts may need semantic dependencies:

- requirement IDs;
- design token IDs;
- API contracts;
- deployment environment;
- data schema;
- market assumptions.

## U7 — Eval runtime

How should we control model/version/tool variance for procedure A/B tests?

## U8 — Independent review economics

When does a different model family materially improve quality enough to justify cost/latency?

## U9 — Telemetry/privacy

Do we want private usage receipts at all? If yes, what can be captured without storing sensitive prompts/transcripts?

## U10 — Design compiler

How should existing web-design knowledge become:

- agent instructions;
- tokens;
- components;
- lint;
- visual regression

without locking the Foundry to one frontend stack?

## U11 — Primitive registry packaging

How should code primitives be consumed?

Possibilities include source registries, packages, templates, generators or copy-owned blocks.

## U12 — Product success evidence

Engineering correctness is not commercial/product validation.

What evidence classes measure:

- usage;
- retention;
- conversion;
- willingness to pay;
- support load;
- external adoption?

## U13 — Foundry throughput measurement

We need a way to know whether Foundry coordination is helping.

Candidate measures:

- time from admitted work to verified output;
- percentage of work reused;
- repeated decisions eliminated;
- escaped defects;
- rework loops;
- context/recovery cost;
- external product evidence.

No global score is accepted yet.
