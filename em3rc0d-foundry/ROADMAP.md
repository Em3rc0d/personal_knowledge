# EM3RC0D Foundry — Roadmap

## MK0 — Mine & Frame

Goal: understand the source system completely enough to design our own Foundry without confusing copied implementation with validated principle.

### P0 — Preserve source

Status: PASS.

- pin upstream commit and tree;
- copy source without nested Git metadata;
- preserve MIT license;
- record provenance;
- keep raw source immutable.

### P1 — Functional distillation

Status: PASS / current package.

Distill:

- lifecycle and routing;
- contracts and manifests;
- shaping and solution selection;
- staged execution;
- proof, review and risk;
- cases and compiled knowledge;
- evals, maturity and promotion;
- runtime/context/coordination;
- visual evidence and output quality;
- executable validators and compilers;
- historical lifecycle corrections.

### P2 — Adaptation model

Status: SEEDED.

Produce GENERATED/INSPIRED architecture for:

- Product Graph;
- Knowledge Graph;
- Artifact Model;
- authority model;
- exact-state evidence and invalidation;
- reusable-capital registry;
- product profiles and conditional gates.

No operational rule is considered promoted merely because it appears in architecture/.

### P3 — MK0 closure audit

Status: PENDING.

Close only when:

- source coverage ledger is complete;
- portable vs source-specific decisions are explicit;
- contradictions and stale-source observations are recorded;
- candidate EM3RC0D mechanisms have provenance labels;
- first dogfood contract is selected;
- no unresolved question prevents the dogfood experiment.

## MK1 — Normalize & Classify

Planned after MK0 closure.

Normalize:

- work-source taxonomy;
- product profiles;
- stage/receipt schema;
- reusable asset classes;
- knowledge relationship types;
- maturity states per asset class;
- authority levels;
- evidence classes;
- invalidation dependency rules.

MK1 must pressure-test the schema against materially different work: product discovery, UI product work, backend/agent work, CLI/tooling, and an existing-product recovery cycle.

## MK2 — Operationalize

Build the minimum operational Foundry:

- canonical Work Contract + machine manifest;
- deterministic validators;
- stage receipt writer;
- current-state resolver;
- product/knowledge graph projections;
- candidate asset registry;
- eval harness;
- case capture;
- minimum installer/runtime adapter.

Do not build an autonomous control plane.

## MK3 — Integrate

Connect:

- personal_knowledge;
- project repositories;
- design system;
- reusable code/component registries;
- GitHub/Vercel and other release surfaces where justified;
- external feedback and usage evidence.

## MK4 — Automate

Only after repeated manual success:

- automatic exact-state routing;
- stale-evidence invalidation;
- artifact generation;
- routine receipt compilation;
- candidate surfacing.

No automatic procedure promotion.

## MK5+ — Certify / Refine

Establish repeated transfer evidence, failure injection, regression suites, external dogfood, product-impact metrics and pruning/deprecation policy.
