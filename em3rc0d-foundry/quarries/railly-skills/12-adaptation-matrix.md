## Abstract behind adapters

Do not make these Foundry requirements:

- RAILLY_SKILLS_REPO;
- FX worker;
- Herdr;
- SkillKit;
- xref internal CLI;
- Vercel AI Gateway;
- macOS Keychain;
- .agents/.claude specific directories;
- one model family/provider.

Instead define required properties:

- canonical source locator;
- isolated worker capability;
- execution identity;
- evidence return;
- package identity;
- telemetry adapter;
- graph/reference adapter;
- secret-store adapter.

## Do not copy blindly

### Exact profile budgets

20/60/180/90 minutes are source defaults, not universal truth.

### Fixed stage count

EM3RC0D product work has design/architecture/market validation surfaces absent from an issue-maintenance pipeline.

### Every experimental skill

Some source skills have explicit evidence gaps or unresolved overlap risk.

### Vercel visual identity

Reuse evidence principles, not brand identity.

### Human overrides without our own evidence debt tracking

If we override, preserve the override and evidence debt explicitly.

### Full run corpus in runtime context

The source itself argues against this.

## Expand beyond Railly

EM3RC0D needs reusable capital classes the source’s skill-centric Foundry does not fully own:

- code primitives;
- UI components;
- full-stack blocks;
- product shells;
- design tokens/rules;
- architecture patterns;
- deployment recipes;
- observability recipes;
- market-research methods;
- launch templates;
- evidence packs.
