# Agent Engineering — MK progression

MKs represent knowledge maturity, not release marketing.

| MK | Name | Exit condition |
|---|---|---|
| MK0 | Mine & Frame | source space, vocabulary, claims, contradictions, risks and candidate rules are evidence-backed |
| MK1 | Normalize & Classify | framework-independent taxonomy is coherent, dimensions are non-overlapping where intended, major examples can be classified consistently |
| MK2 | Operationalize | rules become schemas, templates, checklists, tests and measurable acceptance criteria |
| MK3 | Integrate | contracts connect cleanly with Jett Engineering Method, project architecture, security and delivery workflows |
| MK4 | Automate | validators/eval harnesses can test key invariants automatically and fail closed |
| MK5+ | Certify / Refine | rules survive multiple independent systems, adverse fixtures, version changes and real project evidence |

## Promotion principle

```text
interesting example
      !=
reusable pattern
      !=
validated rule
      !=
certified engineering contract
```

No MK advances because a framework is popular or because a demo succeeds once.
