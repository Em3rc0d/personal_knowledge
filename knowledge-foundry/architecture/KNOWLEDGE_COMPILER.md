# Knowledge Compiler — MK0 Architecture Draft

Provenance: **GENERATED**, informed by current `personal_knowledge` governance and S-001 (`agent-skills`).

Status: **DRAFT / not validated**

## Objective

Compile trustworthy knowledge into an educational artifact without duplicating source canon or losing provenance.

## Compiler stages

### 1. Eligibility

Input must identify:

- source domain / source artifact;
- maturity state;
- provenance;
- known contradictions;
- license/reuse status when external material is involved.

Default input is promoted domain canon.

### 2. Candidate extraction

Extract a bounded teachable capability, not an arbitrary chapter topic.

Good candidate:

> "Design an agent skill with explicit triggers, workflow and verification."

Weak candidate:

> "Everything about AI agents."

### 3. Learner contract

Define:

- target learner;
- prerequisites;
- starting capability;
- desired observable capability;
- non-goals.

### 4. Concept dependency graph

Represent which concepts depend on which others.

A curriculum is an ordering of dependencies, not a list of interesting topics.

### 5. Learning outcomes

Each outcome must use an observable verb and have an assessment path.

Example:

`Design a skill trigger description that distinguishes positive and negative routing cases.`

Not:

`Understand skill routing.`

### 6. Instructional units

A lesson spec may contain:

- outcome;
- prerequisite nodes;
- minimal explanation;
- worked example;
- misconception/anti-pattern;
- practice;
- evidence pointers;
- exit check.

Progressive disclosure is preferred over loading every detail into the first unit.

### 7. Labs

Labs should test application in a realistic artifact.

A lab needs:

- task;
- constraints;
- fixture/context;
- expected evidence;
- failure cases;
- grader/rubric.

### 8. Assessment

Use at least one transfer-oriented check for important outcomes.

Possible layers:

```text
recall
→ explain
→ apply
→ diagnose
→ design
→ defend trade-off
```

Not every lesson needs every layer.

### 9. Source and license manifest

Every product must be able to answer:

- Which canonical nodes support this?
- Which external sources influenced this?
- What may be reproduced?
- What is reference-only?
- What is generated by us?
- What attribution is required?

### 10. Pilot

Run with target learners or a defensible proxy.

Capture:

- completion;
- incorrect mental models;
- friction points;
- assessment performance;
- feedback;
- required revisions.

### 11. Promotion

A product may advance only when its declared gates pass.

## Minimum durable artifact set

```text
PRODUCT_BRIEF
AUDIENCE_PREREQUISITES
CONCEPT_GRAPH
CURRICULUM
LESSON_SPECS
LAB_SPECS
ASSESSMENT_SPEC
SOURCE_LICENSE_MANIFEST
PILOT_RECEIPT
RELEASE_RECEIPT
```

MK0 must validate whether all of these earn their maintenance cost. They are candidates, not yet mandatory canon.

## Design principles

- compile, do not duplicate;
- outcome before content volume;
- dependency order before chapter aesthetics;
- evidence before authority claims;
- transfer before memorization;
- progressive disclosure over context flooding;
- misconceptions are part of instructional design;
- source provenance survives transformation;
- course maintenance is a first-class lifecycle concern;
- retirement is valid when knowledge becomes stale or uneconomic to maintain.
