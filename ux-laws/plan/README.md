# Plan

Execution plans for moving the domain from one MK maturity level to the next.

## Planning rule

No plan may silently promote an unresolved hypothesis into a closed requirement.

Each MK plan should specify:

- objective;
- dependencies;
- inputs;
- work packages;
- acceptance criteria;
- negative tests / failure cases;
- unresolved risks;
- exact exit gate.

## Planned sequence

```text
MK0 evidence inventory
 → MK1 normalization
 → MK2 operational rulebook
 → MK3 design-system bindings
 → MK4 product/agent integration
 → MK5 automated verification
 → MK6+ empirical calibration
```
