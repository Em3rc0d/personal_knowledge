ECHO · Acoustic inference & event delivery

El resultado bruto regresa al scheduler antes de ingresar a la lógica temporal del evento.

Desliza horizontalmente → para explorar el diagrama
Relaciones y alcance del diagrama (alternativa textual)
  1. Replay / RTSP / Mic → Registry + Supervisor
  2. Registry + Supervisor → Decode / Normalize
  3. Decode / Normalize → Bounded AudioBuffer
  4. Bounded AudioBuffer → WindowProducer
  5. WindowProducer → InferenceScheduler
  6. InferenceScheduler → ModelRunner — INFERENCE REQUEST
  7. ModelRunner → InferenceScheduler — RAW_INFERENCE
  8. InferenceScheduler → EventEngine — ORDERED RESULT
  9. EventEngine → ConfirmedEvent
  10. ConfirmedEvent → MQTT
  11. ConfirmedEvent → Event / Result Store
  • SourceRegistry y SourceSupervisor se mantienen identificables.
  • RAW_INFERENCE vuelve al scheduler; el orden y las reglas temporales son responsabilidades distintas.
  • MQTT no es la verdad del evento. La persistencia y publicación son salidas diferentes.
  • No se representan health side-channels, fallos, retries ni despliegue: consultar los contratos fuente.
