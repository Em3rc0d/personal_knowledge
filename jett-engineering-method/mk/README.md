# Jett Engineering Method — MK Model

MKs represent **maturity**, not arbitrary versions.

## Base semantics

### MK0 — Mine & Frame
Question: **What exists, what is the actual problem, and what boundaries matter?**

Typical work:
- source discovery;
- recovery of prior decisions;
- problem framing;
- provenance;
- vocabulary;
- initial quarries;
- contradiction discovery;
- open questions.

### MK1 — Normalize & Classify
Question: **Can the mined knowledge become a coherent model?**

Typical work:
- taxonomy;
- normalization;
- deduplication;
- terminology;
- classification;
- contradiction resolution;
- canonical concepts.

### MK2 — Operationalize
Question: **Can the knowledge become usable rules or artifacts?**

Typical work:
- rulesets;
- schemas;
- checklists;
- decision trees;
- templates;
- evaluation criteria;
- executable policies.

### MK3 — Integrate
Question: **Can the knowledge operate coherently with other domains/systems?**

Typical work:
- cross-domain contracts;
- shared abstractions;
- compatibility;
- dependency boundaries;
- integration evidence.

### MK4 — Automate
Question: **What can be automated without losing control, provenance or fail-closed behavior?**

Typical work:
- agents;
- scripts;
- automated validation;
- pipelines;
- generators;
- evidence collection.

### MK5+ — Certify / Refine
Question: **How strong, reproducible and durable is this knowledge?**

Typical work:
- certification;
- held-out fixtures;
- counterexamples;
- regressions;
- reproducibility;
- resilience;
- performance where claimed;
- operational refinement.

## Gate rule

A MK never closes because enough files exist. It closes only when its acceptance criteria are satisfied with reviewable evidence.

Each domain may specialize this model but must document the specialization explicitly.
