# MK0 — Mine & Frame

## Goal

Establecer la foundation de Jett Engineering Method sin sobrecertificarla.

MK0 responde:

> **¿Qué método estamos usando realmente, qué problemas intenta prevenir y cuáles son sus boundaries?**

## Scope

- purpose and role of JEM;
- lifecycle phases;
- permanent/contextual gates;
- five truth classes;
- provenance and claim discipline;
- branch/canon rules for `personal_knowledge`;
- base MK maturity semantics;
- relationship with HESTIA and Knowledge Environment.

## Non-scope

- external-standard equivalence;
- automated enforcement;
- formal certification;
- complete benchmark against SDLC/SRE/security standards;
- exhaustive project case library.

## Acceptance criteria

- [x] problem/purpose framed;
- [x] internal provenance recorded;
- [x] lifecycle and boundaries defined;
- [x] gates defined;
- [x] truth classes separated;
- [x] claim discipline defined;
- [x] MK semantics defined;
- [x] stage folders bootstrapped;
- [ ] root monorepo documentation updated;
- [ ] full branch diff reviewed;
- [ ] `STATUS.md` promoted from `IN REVIEW` to `CLOSED` only after review.

## Promotion rule

MK0 may merge to `main` only after the unchecked criteria are satisfied. Closing MK0 means the foundation is coherent enough to serve as internal canon; it does **not** mean JEM is externally certified or complete.
