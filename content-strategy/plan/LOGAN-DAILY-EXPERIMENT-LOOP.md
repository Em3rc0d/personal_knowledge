# Logan Daily Experiment Loop

Status: `GENERATED / OPERATIONAL PLAN`  
Profile: `Logan / mi.logan.pe`

## Daily cycle

```text
1. READ YESTERDAY
2. UPDATE LEDGER
3. MINE NEW PROBLEMS
4. SELECT 4 EXPERIMENTS
5. PRODUCE
6. PUBLISH
7. MEASURE T+2h
8. MEASURE T+24h
9. MEASURE T+7d
10. PROMOTE / REWRITE / KILL
```

## 1. Read yesterday before choosing today

Do not begin with “what four automotive topics sound interesting?”.

Read:

- what earned distribution;
- what earned comments, shares or saves;
- what caused profile curiosity when visible;
- what search language appeared;
- what failed despite a useful topic;
- what format has been overused;
- what topics / symptoms / diagnoses are blocked by the no-repeat rule.

The next batch should respond to evidence.

If a metric is unavailable, record `UNKNOWN`; never fabricate attribution.

## 3. Mine problems, not only components

Backlog priority:

1. surfaced TikTok search language;
2. audience comments/questions;
3. real symptoms from maintenance/ownership;
4. strong diagnostic clusters;
5. common misdiagnoses;
6. components reframed around a real symptom.

Preserve natural query wording where possible.

## 4. Select four experiments

Each post should have an explicit job and, when possible, a hypothesis.

Example:

```text
TOPIC             rough idle after maintenance
ROLE              diagnostic / comments
HYPOTHESIS        symptom-first framing will create more interaction than component-first framing
FORMAT            3-slide carousel
HOOK              “¿Tu ralentí quedó peor después del servicio?”
CTA               ask whether it happens cold or hot
NOVELTY_CHECK     PASS
```

A post without a testable hypothesis may still be published, but label it `EXPLORATORY` rather than treating it as controlled evidence.

## 5. Production gate

Before publishing:

- hook readable in <2 seconds;
- promise mechanically defensible;
- body resolves the hook;
- diagnosis preserves uncertainty when multiple causes exist;
- no accidental duplicate exists;
- visual quality passes the account standard;
- CTA has one primary job;
- hashtags describe the actual content;
- carousel slides are separately usable when required.

Any critical failure → revise before publication.

## 6. Measurement windows

### T+2h

Question:

> Did the package earn early attention/distribution?

Directional only.

### T+24h

Question:

> Did the post perform against its intended job relative to the current account baseline?

Primary first classification point.

### T+7d

Question:

> Did long-tail distribution, search or delayed interaction change the judgment?

Use to finalize the learning record.

## 7. GREEN / YELLOW / RED

### GREEN

Provisional condition:

- exceeds rolling median in at least two objective-relevant metrics; or
- produces an unusually strong downstream signal even with ordinary views.

Action:

- identify the mechanism that may have won;
- test up to 3 materially different variations within ~72h;
- do not duplicate the same post verbatim.

### YELLOW

Condition:

- useful topic with weak hook, visual, format or CTA;
- promising signal exists but the whole pattern is not ready for promotion.

Action:

- change one or two variables;
- document why the retry is different.

### RED

Condition:

- three materially different attempts fail against the intended objective; or
- the angle repeatedly creates shallow views with no useful downstream behavior and no strategic reason remains.

Action:

- archive the angle;
- preserve evidence;
- do not recycle it because the backlog is empty.

## 8. Weekly review

Review at least:

```text
reach trend
interaction trend
profile-conversion trend
follow trend
search trend
best topic clusters
best hook families
best formats
best visual patterns
best CTAs
failed assumptions
blocked/repeated concepts
next-week hypotheses
```

Never rank the week by views alone.

## 9. Falsification questions

Every weekly review must ask:

- Which belief lost support?
- Which winner failed to repeat?
- Which format may look strong only because of one topic?
- Which topic may look weak only because of packaging?
- Did the account improve conversion, or only distribution?
- Did stronger hooks increase attention without harming trust/technical integrity?

## 10. Scaling rule

Keep four posts/day only while:

```text
visual_quality = PASS
novelty = PASS
technical_integrity = PASS
measurement = SUSTAINABLE
```

If cadence creates filler, repetition or weak assets, reduce output before lowering standards.

The purpose of cadence is **learning velocity**, not vanity volume.
