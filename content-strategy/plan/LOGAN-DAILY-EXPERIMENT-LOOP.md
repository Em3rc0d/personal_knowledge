## 1. Daily cycle

```text
READ CURRENT DATA
→ UPDATE TOPIC LEDGER
→ MINE NEW PROBLEMS
→ SELECT 4 DISTINCT ROLES
→ WRITE HYPOTHESIS PER POST
→ NOVELTY GATE
→ TECHNICAL GATE
→ PRODUCE
→ PUBLISH
→ T+2h
→ T+24h
→ T+72h
→ T+7d
→ SCALE / HOLD / KILL MECHANISM
```

Never start with:

> “What four car topics can we post today?”

Start with:

> “What four different growth hypotheses can we test today using topics we have not already published?”

## 2. Topic ledger before generation

Each candidate receives:

```text
topic_key
symptom_key
decision_key
status: PUBLISHED | COOLDOWN | NEW
last_used
notes
```

Rules:

```text
PUBLISHED → reject by default
COOLDOWN  → reject unless materially different and explicitly justified
NEW       → eligible
```

A wording change is not novelty.

Until all 89+ historical publications are normalized, manually compare candidates against known recent history and project memory.

## 3. Mine demand

Priority:

1. TikTok Search / Creator Search Insights;

3. comments and real audience questions;
4. real ownership / workshop decisions;
5. common diagnosis errors;
6. new tuning/performance questions;

Preserve the natural way people ask the question.

## 4. Select four roles

### A — SEARCH

Question:

> What exact problem is somebody already trying to solve?

Required fields:

```text
target_query
hook
search wording in caption
expected search intent
```

### B — HERO

Question:

> What is the strongest broad-recognition attempt today?

Required:

- strongest first-frame;
- one clear promise;
- broad driver relevance;
- no unnecessary technical vocabulary.

### C — SHARE ENGINE

Question:

> What would a viewer naturally send to another driver?

Required:

- forwarding reason;
- compact utility / recognition;
- no dependence on “share this” wording.

### D — LAB

Question:

> What one new variable are we learning about?

Test only one primary variable where possible:

```text
hook family
format
visual style
POV
question framing
technical depth
tuning/performance
meme structure
audio / motion
```

## 6. Production gate

Before publish:

- topic is genuinely new;
- hook can be understood immediately;
- hook promise is technically defensible;
- body resolves the hook;
- uncertainty is visible when multiple causes exist;
- one dominant idea per slide/frame;
- visual quality passes;
- no blurred / low-resolution asset;
- carousel files are separate and 9:16;
- caption opens with useful natural language;
- hashtags classify the actual topic;
- interaction trigger is specific or omitted;
- public product promotion is absent.

Critical failure → revise.

## 11. Measurement windows

### T+2h

Ask:

- did the package get early distribution?
- are there obvious technical/visual failures?
- did Search indexing begin if visible?

Action:

- observe;
- do not overreact.

### T+24h

Primary first judgment.

Compare with:

- role-specific recent median;
- account rolling median;
- objective-relevant ratios.

Ask:

- did people consume?
- did the post produce its intended action?
- is this topic or packaging likely responsible?

### T+72h

Ask:

- did recommendation distribution continue?
- did Search contribution appear later?
- did shares or saves create delayed movement?
- did a weak T+24h post improve?

### T+7d

Finalize learning record:

- stabilized views;
- Search;
- interaction;
- profile/follow effects when available;
- mechanism classification.

## 13. SCALE / HOLD / KILL

### SCALE

Scale the **mechanism**, not the topic.

Candidate when:

- distribution clearly beats current rolling baseline; and
- at least one meaningful secondary signal supports it: retention/completion, shares, comments, search, profile action or follows.

Action:

> reuse structure with a materially new topic.

### HOLD

Use when:

- views are ordinary but Search / shares / saves / profile action are useful; or
- topic seems sound but packaging is mixed.

Action:

> preserve learning, change one major variable on a new topic.

### KILL

Use when:

- a format/mechanism repeatedly underperforms across materially different topics; or
- it produces shallow views with no useful downstream action.

Action:

> archive mechanism; do not revive because the backlog is empty.

Never kill a topic solely because one execution failed if packaging clearly failed.

## 14. 14-day experiment program

### Days 1–4 — Hook families

Keep topic novelty strict.

Test across roles:

- risk;
- money;
- diagnostic uncertainty;
- decision conflict.

Goal: identify attention patterns without reusing topics.

### Days 5–7 — Visual comprehension

Test:

- real photo + annotation;
- premium infographic;
- A/B split visual;
- POV / human situation.

Goal: learn stop power + comprehension speed.

### Day 7 review

Evaluate:

- hook family;
- role;
- format;
- Search contribution;
- shares;
- comments;
- profile behavior;
- failures.

### Days 8–11 — Retention structure

Test:

- 3-slide vs 4-slide only when idea can support both;
- answer timing;
- one clue per slide;
- short video when motion/sound truly helps.

Do not publish the same topic twice for A/B. Compare mechanisms across different but similarly broad topics and label the evidence as quasi-experimental.

### Days 12–14 — Interaction mechanism

Test:

- A/B decision ending;
- concrete diagnostic question;
- no explicit CTA;
- forwardable checklist.

### Day 14 review

Decide:

```text
PROMOTE mechanisms
HOLD uncertain mechanisms
ARCHIVE weak mechanisms
REFRESH blocked topic ledger
SET next 14-day hypotheses
```

## 15. Weekly protocol

Every week:

1. export / read TikTok Analytics;
2. record latest traffic-source split;
3. collect Search queries;
4. inspect Creator Search Insights / content gaps where available;
5. update `PUBLISHED / COOLDOWN / NEW`;
6. rank by **role-specific performance**, not views alone;
7. extract mechanisms from winners;
8. check whether winners repeated;
9. identify false beliefs;
10. set next week’s experiments.

Mandatory falsification questions:

- Which belief lost support?
- Which “winner” failed to repeat?
- Did stronger hooks actually improve downstream behavior?
- Did Search grow because of intentional query alignment or coincidentally?
- Is four posts/day still improving learning velocity?
- Are we producing fatigue or semantic repetition?

## 16. Cadence rule

Keep four posts/day only while:

```text
NOVELTY             PASS
TECHNICAL_INTEGRITY PASS
VISUAL_QUALITY      PASS
MEASUREMENT         SUSTAINABLE
```

If one fails repeatedly, reduce cadence before lowering standards.
