# Logan Editorial Operating System

Status: `GENERATED / MK0 WORKING CANON`  
Profile: `Logan / mi.logan.pe`  
Platform: `TikTok`

## 1. Objective

Use content as a controlled growth system rather than a stream of isolated automotive posts.

Primary funnel:

```text
REACH
  ↓
VIEW
  ↓
INTERACTION
  ↓
PROFILE VISIT
  ↓
FOLLOW
  ↓
FUTURE TRUST / CONVERSION
```

Current account evidence suggests the next major optimization target is **turning distributed views into intentional user actions**.

## 2. Core promise

> **Te explico qué podría estar pasando con tu carro antes de que cambies piezas a ciegas.**

The account should feel:

- useful before entertaining;
- technically curious rather than mechanically sensational;
- confident without pretending diagnostic certainty;
- fast to understand on mobile;
- visually premium;
- oriented to real symptoms and decisions.

It should not become:

- a generic “car facts” page;
- a lifestyle repost account;
- a component dictionary;
- a fear-based mechanic page;
- a clickbait page that does not resolve its own hook.

## 3. Aggressiveness contract

“Aggressive” means **high information tension**, not falsehood.

Allowed:

- direct symptom framing;
- strong contrast;
- consequences when technically justified;
- specific problem language;
- curiosity gaps resolved in-post;
- provocative but answerable questions;
- “before replacing X, check Y” when defensible;
- strong first-frame visual hierarchy.

Blocked:

- fabricated danger;
- fake certainty;
- catastrophic diagnosis from one ambiguous symptom;
- unrelated shock phrases;
- generic “NO VAS A CREER ESTO” without real payoff;
- hiding promised information behind a forced comment CTA.

Hook integrity rule:

```text
attention gained <= value delivered
```

## 4. Default diagnostic architecture

```text
1. SYMPTOM
   “¿Tu carro hace X?”

2. INTRIGUE
   “No siempre significa Y.”

3. PLAUSIBLE CAUSES
   prioritized, not exhaustive

4. HOW TO DIFFERENTIATE
   visible clue / scanner data / operating condition / simple observation

5. NEXT STEP
   what to verify before replacing a part

6. CTA
   one action aligned with the post objective
```

The component is often the technical answer, not the editorial hook.

## 5. Format rules

### Short carousel

Use when understanding benefits from progression.

```text
Slide 1  symptom / tension
Slide 2  hidden explanation or causes
Slide 3  differentiation / diagnostic clue
Slide 4  action + CTA
```

Do not add slides merely to make a carousel longer.

### Single image

Use when one visual comparison, misconception or warning can be understood almost immediately.

### Meme / reaction

Use as a minority format for relatability and forwarding behavior. It must remain connected to the automotive identity.

### Video

Use when motion, sound, sequence or physical behavior materially improves explanation. A slideshow with transitions is not automatically superior to a strong carousel.

## 6. Topic selection

Prioritize candidates that satisfy at least two:

1. real symptom language;
2. common uncertainty / misdiagnosis;
3. useful distinction teachable quickly;
4. visually explainable;
5. naturally saveable/shareable/commentable;
6. connected to prior strong diagnostic clusters;
7. appears in search-query evidence;
8. has not been used recently.

Prefer:

> “¿Por qué tu carro pierde fuerza cuando aceleras?”

instead of:

> “Sensor MAF: funcionamiento”.

## 7. No-repeat contract

A post is a repeat when the underlying value proposition is effectively the same even if the wording changes.

Check:

```text
topic
symptom
diagnosis
hook mechanism
visual metaphor
carousel sequence
punchline
CTA structure
```

Repetition is allowed only when explicitly documented as:

- controlled variation;
- Part 2 / continuation;
- correction;
- updated evidence;
- deeper treatment requested by the audience.

The goal is not infinite novelty. The goal is to prevent **accidental editorial duplication**.

## 8. Daily batch contract

Current cadence: **4 posts/day**.

This is an experiment-throughput strategy, not a platform truth.

Preferred role diversity:

```text
A  high-reach symptom / misconception
B  technical diagnostic explainer
C  saveable distinction / checklist
D  shareable reaction / comparison / unexpected fact
```

Each slot should vary at least one of:

- topic cluster;
- interaction objective;
- format;
- technical depth.

If cadence lowers quality or novelty, output must be reduced before standards are lowered.

## 9. CTA contract

Use one primary CTA objective.

### Comments

Ask for a concrete condition or experience.

Weak:

> “¿Qué opinas?”

Stronger:

> “¿Te pasa en frío, al frenar o todo el tiempo?”

### Saves

Make the post reference-worthy.

> “Guárdalo para revisarlo antes de comprar piezas.”

### Follows

Promise a coherent future stream.

> “Sigue la cuenta si quieres aprender a diferenciar fallas antes de gastar.”

### Shares

Create useful forwarding behavior.

> “Mándaselo a quien está por cambiar media suspensión por una vibración.”

CTA language should remain natural; not every post needs an explicit command.

## 10. Hashtag contract

For Logan, treat hashtags as semantic metadata.

Suggested shape:

```text
2–4 domain tags
+ 1–2 topic-specific tags
```

Examples:

```text
#MecanicaAutomotriz
#DiagnosticoAutomotriz
#Autos
#Motor
#PCV / #OBD2 / #Frenos / topic-specific
```

Do not rely on unrelated tags such as `#money`. Generic reach tags such as `#fyp` should not replace classification clarity.

This is profile-specific. It does not automatically override conventions on Content Seller or other channels.

## 11. Visual quality contract

Minimum:

- strong mobile-first hierarchy;
- one dominant message per slide;
- readable text at phone size;
- deliberate automotive imagery or diagrams;
- no unfinished-template appearance;
- consistent but non-repetitive art direction;
- slide progression that visually changes when the information changes;
- technical visuals must clarify, not merely decorate;
- separate export-ready slide assets when a carousel is requested.

Four posts/day does not authorize four low-quality assets.

## 12. Content-mix hypothesis

Current provisional mix:

```text
85–90%  diagnostic / technical / problem-solving
10–15%  lifestyle / humor / brand personality
```

`INFERRED / provisional`

This mix is not an identity commitment. It must change if evidence changes.

## 13. Search-to-backlog rule

User queries are first-class research inputs.

Priority backlog sources:

1. TikTok search / Creator Search Insights / surfaced search queries;
2. comments and audience questions;
3. real maintenance / ownership symptoms;
4. high-performing diagnostic clusters;
5. common mechanical misconceptions;
6. component knowledge reframed as a symptom/problem.

Preserve original user wording whenever possible because it captures actual vocabulary.

## 14. Measurement semantics

Default windows:

```text
T+2h   early package/distribution signal
T+24h  primary post-performance decision point
T+7d   long-tail / search / stabilized comparison
```

Track when available:

```text
views
watch time / completion / slide-through
likes
comments
shares
saves
profile visits
follows
search traffic / queries
clicks / registrations / later sales
```

Raw views alone are insufficient.

## 15. Promotion logic

Working classification:

```text
GREEN   outperform rolling median in >=2 objective-relevant metrics
YELLOW  useful topic, weak or mixed packaging
RED     3 materially different attempts fail against intended objective
```

GREEN action: test up to three materially different variations within about 72h.

YELLOW action: change one or two variables with a documented reason.

RED action: archive the angle and preserve evidence.

These thresholds remain provisional until normalized longitudinal data exists.
