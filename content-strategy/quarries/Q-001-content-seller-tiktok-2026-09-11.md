## 3. Strategic problem identified

The existing account can teach technical topics, but pure technical-explainer output risks becoming:

```text
useful
but visually/structurally repetitive
and weak at identity / aspiration / conversion
```

The opportunity is to build a broader identity:

> Systems/IT student → real builder → engineer who uses AI intelligently.

This creates a larger addressable audience than experienced developers only and is strategically aligned with future Prompt Machine users.

## 5. Positioning hypothesis

Preferred:

> **Technology explained for people who are learning to build real things.**

Secondary association built over time:

> **AI is a tool for thinking and working better, not for copying answers.**

Avoid collapsing the identity into:

```text
programming facts page
prompt-selling page
AI hacks page

```

Each can be a content ingredient; none should become the whole brand.

## 6. Aggressive growth — what it means here

`GENERATED`

Aggressive means:

- stronger first-frame contrast;
- recognizable stakes;
- curiosity gaps with a real payoff;
- contrarian but defensible framing;
- identity hooks (“si estudias Sistemas...”, “esto te pasa cuando...”);
- outcome-oriented language;
- clearer visual hierarchy;
- deliberate series and follow behavior.

Aggressive does **not** mean relying on generic wording such as:

```text
NO VAS A CREER ESTO 😱😱😱
```

unless the content genuinely supports that tone. The preferred model is **high-friction curiosity + substance**, not empty sensationalism.

## 10. Curriculum transformation rule

Bad:

> “Hoy hablaremos del curso Sistemas Operativos.”

Better:

> “Tu backend no vive solo.”

Bad:

> “Tema: Sistemas Distribuidos.”

> “Tu aplicación funciona perfecto en una computadora. Ahora ponla en tres.”

The course supplies knowledge; the post starts from a recognizable problem, consequence, misconception or project situation.

## 11. Prompt Machine seeding

Do not sell prompts aggressively while the account is still building trust.

Teach these concepts first:

```text
context
workflow
constraints
output contract
review
iteration
```

Content examples:

- why a task without context produces weak AI output;
- why one giant prompt should not contain an entire process;
- how to turn a rubric into a workflow;
- how to use AI to understand a difficult course;
- how to review AI output instead of accepting it blindly.

The desired future launch story is:

> “I organized the workflow system I have been teaching into something reusable.”

not:

> “I suddenly started selling prompt packs.”

## 12. Novelty / no-repeat contract

Before approving an idea, compare against recent content on:

```text
topic
angle
hook semantic pattern
creative structure
visual pattern
same-batch similarity
```

Blocked by default:

- same topic with trivial wording change;
- same lesson under a different title;
- same joke or meme premise;
- same carousel progression;
- repeated “X things...” structure too close together;
- same visual classifier/comparison repeatedly;
- a disguised Part 2 unless continuation is explicitly desired.

Operational preference: avoid topic reuse for several days and preferably about a week when supply allows, while treating semantic repetition—not just dates—as the stronger rule.
