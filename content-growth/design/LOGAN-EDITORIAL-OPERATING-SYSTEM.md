# Logan Editorial Operating System

Status: `GENERATED / MK0 working canon`  
Account: `mi.logan.pe`  
Platform: TikTok

## Objective

Use content as a controlled growth system rather than a stream of isolated posts.

Primary funnel:

```text
REACH
  ↓
VIEW
  ↓
INTERACTION
  ↓
PROFILE VISIT
  ↓
FOLLOW
  ↓
FUTURE TRUST / CONVERSION
```

For the current Logan stage, the dominant optimization target is the middle of this funnel: **turn distributed views into intentional user actions**.

---

## Editorial stance

### Core promise

> Explain the likely reason behind a real car symptom before the viewer starts replacing parts blindly.

### Content identity

The account should feel like:

- a fast diagnostic guide;
- mechanically curious, not sensationally ignorant;
- technical enough to be useful;
- simple enough to understand in seconds;
- visually premium;
- confident without pretending certainty where diagnosis requires inspection.

It should not feel like:

- a generic “car facts” page;
- a repost/lifestyle account;
- a dictionary of components;
- a fear-based mechanic page that diagnoses every symptom as catastrophic;
- a clickbait account whose body does not deliver the hook.

---

## Aggressiveness model

“Aggressive” means **high information tension**, not false claims.

### Allowed aggressiveness

- direct problem framing;
- strong contrast;
- consequence framing when technically justified;
- specific symptom language;
- curiosity gaps that are resolved inside the post;
- decisive visual hierarchy;
- provocative but answerable questions;
- “don’t replace X yet” or “before changing X, check Y” when defensible.

### Disallowed / weak aggressiveness

- fabricated danger;
- fake certainty;
- screaming without substance;
- generic “NO VAS A CREER ESTO” packaging disconnected from the actual value;
- bait that forces the user to comment merely to obtain the promised answer;
- sensational diagnosis from a symptom that has many plausible causes.

### Hook quality test

A hook is acceptable only if:

```text
attention gained
≤
value actually delivered
```

The post must pay back the attention debt.

## Default content architecture

### Diagnostic post

```text
1. SYMPTOM
   “¿Tu carro hace X?”

2. INTRIGUE
   “No siempre significa Y.”

3. PLAUSIBLE CAUSES
   prioritized, not exhaustive

4. HOW TO DIFFERENTIATE
   visible clue / scanner data / condition / simple observation

5. NEXT STEP
   what to inspect or verify before replacing a part

6. CTA
   one action aligned with the post objective
```

### Short carousel

Preferred when the concept needs progression:

```text
Slide 1  aggressive symptom hook
Slide 2  hidden explanation / causes
Slide 3  differentiation / diagnostic clue
Slide 4  action + CTA
```

Do not add slides merely to increase carousel length.

### Single-image post

Use when one visual comparison or one misconception can be understood almost immediately.

### Meme / reaction post

Use as a minority format for emotional recognition and shareability, but it should remain connected to the automotive identity.

### Video

Use only when motion, sound, sequence or physical behavior materially improves the explanation. A slideshow with transitions is not automatically better than a strong carousel.

## Topic selection system

Prioritize topic candidates that satisfy at least two of these:

1. real symptom language people use;
2. high uncertainty / common misdiagnosis;
3. a useful distinction can be taught quickly;
4. visually explainable;
5. naturally invites saves/shares/comments;
6. connected to prior strong diagnostic clusters;
7. appears in search-query evidence;
8. has not been used recently.

### Topic framing rule

Prefer:

> “¿Por qué tu carro pierde fuerza cuando aceleras?”

over:

> “Sensor MAF: funcionamiento”.

Component knowledge is the **answer**, not necessarily the hook.

---

## No-repeat contract

A post is considered a repeat when it reuses the same underlying value proposition even if wording changes.

Check at least:

- topic;
- symptom;
- diagnosis;
- hook mechanism;
- visual metaphor;
- carousel sequence;
- punchline;
- CTA structure.

Repetition is allowed only when explicitly labeled as one of:

- controlled variation;
- follow-up / Part 2;
- updated evidence;
- correction;
- deeper level of the same topic requested by the audience.

The goal is not infinite novelty. The goal is to avoid **accidental editorial duplication**.

---

## Daily batch rule

Current operating cadence: **4 posts/day**.

This is not treated as a platform truth. It is a deliberate high-throughput experiment strategy.

Each daily batch should ideally diversify:

- topic cluster;
- interaction objective;
- visual format;
- level of technical depth.

Example batch shape:

```text
Post A  high-reach symptom / misconception
Post B  technical diagnostic explainer
Post C  highly saveable checklist / distinction
Post D  shareable reaction, comparison or unexpected fact
```

All four still belong to the same account promise.

## CTA system

Use **one primary CTA** per post.

### If objective = comments

Ask for a concrete experience, symptom or choice.

Bad:

> “¿Qué opinas?”

Better:

> “¿Te pasa en frío, al frenar o todo el tiempo?”

### If objective = saves

Make the post reference-worthy.

> “Guárdalo para revisarlo antes de comprar piezas.”

### If objective = follows

Promise a coherent future stream, not a vague request.

> “Sigue la cuenta si quieres aprender a diferenciar fallas antes de gastar.”

### If objective = shares

Create identity or utility worth forwarding.

> “Mándaselo a quien está por cambiar media suspensión por una vibración.”

CTA language should remain natural; do not force every post to end with a command.

## Hashtag system

Hashtags are metadata, not magic distribution switches.

Default structure:

```text
2–4 domain tags
+ 1–2 topic-specific tags
```

Examples:

- `#MecanicaAutomotriz`
- `#DiagnosticoAutomotriz`
- `#Autos`
- `#Motor`
- plus `#PCV`, `#OBD2`, `#Frenos`, etc. when relevant.

Avoid unrelated or generic tags whose main function is wishful reach (`#money`, indiscriminate `#fyp`, etc.).

---

## Visual quality contract

Visuals should be high-quality enough that the account looks intentional before the viewer reads the caption.

Minimum qualities:

- strong mobile-first hierarchy;
- one dominant message per slide;
- readable text at phone size;
- deliberate automotive imagery or diagrams;
- no “template dump” appearance;
- consistent but not repetitive art direction;
- enough contrast between slides to preserve progression;
- technical visuals must clarify, not decorate.

Quality is a gate. Four posts/day does not authorize four mediocre assets.
