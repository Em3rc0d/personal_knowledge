# Logan Daily Experiment Loop

Status: `GENERATED / operational plan`  
Purpose: turn the 4-post cadence into a measurable learning system.

## Daily cycle

```text
1. READ YESTERDAY
2. UPDATE LEDGER
3. MINE NEW PROBLEMS
4. SELECT 4 EXPERIMENTS
5. DESIGN / PRODUCE
6. PUBLISH
7. MEASURE T+2h
8. MEASURE T+24h
9. MEASURE T+7d
10. PROMOTE / REWRITE / KILL
```

---

## 1. Read yesterday before choosing today

Do not start with “what four topics sound interesting?”.

Start with:

- what got distribution;
- what earned interaction;
- what caused profile visits / follows if visible;
- what search language appeared;
- what failed despite a good topic;
- what format has been overused;
- what topics are now blocked by the no-repeat window.

The next batch should be a response to evidence.

---

## 2. Maintain an editorial ledger

Minimum fields per post:

```text
post_id
date
time
topic_cluster
symptom
technical_answer
hook_type
format
slide_count
cta_objective
hashtags
views_2h
views_24h
views_7d
likes
comments
shares
saves
profile_visits
follows
search_terms
classification: GREEN | YELLOW | RED
notes
```

If the platform does not expose a metric per post, leave it `UNKNOWN`; do not fabricate attribution.

---

## 3. Mine problems, not just components

Backlog sources in priority order:

1. TikTok search / Creator Search Insights / surfaced search queries;
2. comments and audience questions;
3. symptoms encountered in real maintenance / ownership;
4. high-performing diagnostic clusters;
5. mechanically important misconceptions;
6. component knowledge reframed as a symptom/problem.

Store the original user-language query whenever possible. It is evidence of vocabulary.

---

## 4. Select four experiments

Each post must have an explicit reason to exist.

Example decision record:

```text
TOPIC: rough idle after maintenance
HYPOTHESIS: symptom-first framing will outperform component-first framing
FORMAT: 3-slide carousel
PRIMARY OBJECTIVE: comments
HOOK: “¿Tu ralentí quedó peor después del servicio?”
CTA: ask whether it happens cold or hot
NOVELTY CHECK: PASS
```

A post without a hypothesis can still be published, but should be labeled **exploratory**, not treated as a controlled experiment.

---

## 5. Production gate

Before publication, check:

- hook is legible in <2 seconds;
- the promise is technically supportable;
- the body answers the hook;
- no accidental duplicate exists;
- visual quality is consistent with the premium account standard;
- CTA matches one objective;
- hashtags classify the actual content;
- diagnosis language preserves uncertainty when several causes are plausible.

Fail any critical item → revise before publishing.

---

## 6. Measurement windows

### T+2h

Question:

> Did the package earn initial distribution / attention?

Use for early directional evidence only.

### T+24h

Question:

> Did the post perform against its primary objective relative to current account baselines?

This is the default first classification point.

### T+7d

Question:

> Did the post have long-tail distribution, search value or delayed interaction that changes the judgment?

Use to finalize the learning record.

---

## 7. Classification

### GREEN

Condition, provisional:

- exceeds rolling median in at least **two metrics relevant to its objective**, or
- produces an unusually strong downstream signal even if views are ordinary.

Action:

- extract the winning mechanism;
- generate up to 3 materially different variations within ~72h;
- do **not** duplicate the same post verbatim.

### YELLOW

Condition:

- topic appears useful but hook, format, CTA or visual package underperforms;
- some metric is promising but not enough to promote the whole pattern.

Action:

- change one or two variables;
- retry with a documented reason.

### RED

Condition:

- three materially distinct attempts fail against the intended objective;
- or the topic repeatedly attracts views with no useful downstream behavior and no strategic reason to keep it.

Action:

- archive the angle;
- preserve evidence;
- do not recycle it merely because the backlog is empty.

---

## 8. Weekly review

Once per week, summarize:

```text
reach trend
engagement trend
profile conversion trend
follow trend
search trend
best topic clusters
best hook mechanisms
best formats
best CTAs
failed assumptions
new blocked/repeated topics
next-week hypotheses
```

Avoid ranking by views alone.

---

## 9. Scaling rule

Four posts/day remains valid only while:

```text
quality stays above gate
AND
novelty stays above gate
AND
measurement remains sustainable
```

If cadence causes filler, repetition or weak visuals, reduce output before lowering the quality contract.

The purpose of cadence is **learning velocity**, not content volume as vanity.
